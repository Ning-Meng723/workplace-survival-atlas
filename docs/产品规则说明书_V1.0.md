# 一、产品目标与边界

产品名：《你的职场生存状态图鉴》

用户答完 20 道情境题，得到五样东西：

1. 五维雷达图（钱包 W / 生命值 L / 精神状态 M / 职场气候 C / 成长空间 G）
2. 一个主物种（树懒 / 炸毛猫 / 水豚 / 狐狸 / 企鹅）
3. 一个副称号（15 个里按分数查表，不随机）
4. 一个整体职场状态（需要回血 / 勉强维持 / 基本在线 / 状态不错）
5. 一段由"物种 + 状态 + 两条维度证据"拼出来的判词，以及一张分享卡片

**明确不做的事**：

- 不宣称"科学测评""心理测量""职业诊断"
- 不提供辞职建议、职业规划结论、心理干预建议
- 不显示"你超过了 N% 的打工人"（需要真实人群分布，拿到 ≥200 份真实样本前不得上线）
- 不做人格判断（"你就是懒"这类绝对化表述一律禁止）

# 四、计分对象与数据结构（V1.0 新增）

## 1. 分值绑 option_id，不绑字母、不绑文本

`题库.json` 每题 4 个选项，每个选项有：

```
option_id   形如 Q01-O1 … Q20-O4（80 个，全局唯一）
score       1 / 2 / 3 / 4（1=较差，2=偏弱，3=较好，4=很好）
text        选项文案
```

**后台取分规则**：拿到用户提交的 `option_id`，查表取 `score`。**不看** A/B/C/D、**不看**显示顺序、**不看**文案。

为什么不按文本取分：文案一改（哪怕是加个标点）就取不到分了；而 option_id 是稳定的。文本只用于人工核对，`核对计分表.js` 会校验"option_id ↔ 文本"没被错配。

**允许的改动**：选项文案可以改（改完必须重跑五节的两条命令同步计分表）。
**不允许的改动**：删/换 option_id；把两个选项的 option_id 交换；用 A/B/C/D 当主键。

## 2. 维度与换算

每个维度 4 题，原始总分 **4–16 分**。

```
维度指数 = (维度原始总分 - 4) / 12 × 100
```

**指数只有 13 个可能值**：0 / 8.3 / 16.7 / 25 / 33.3 / 41.7 / 50 / 58.3 / 66.7 / 75 / 83.3 / 91.7 / 100。

> 这不是连续分布。允许出现 37.2 分的设计（比如"你 37.2 分"这种文案）是错的——真实用户给不出这个值。

### 2.1 允许跳过题目后的换算（v1.2 / algorithm v1.1 新增）

用户可以不回答某道题（主动跳过）。跳过的题**不产生分值**：既不记 0 分，也不补中间分，只是不进下面的 `S` 和 `n`。

```
n_d = 该维度有效回答的题数（只可能是 2 / 3 / 4）
S_d = 该维度已回答题目的分数之和
维度指数 = ((S_d - n_d) / (3 × n_d)) × 100
```

- `n_d = 4` 时：`(S-4)/(3×4)×100 = (S-4)/12×100`，与上面那条**完全同一个式子**，所以全答用户的结果一字不变。
- `n_d = 3`：指数步长变成 11.1（可能出现 44.4 这种不在 13 档上的值）；`n_d = 2`：步长 16.7。
- **最低回答要求**：每个维度至少 **2 题**有效回答。
  - 2 题：允许计算，但结果页要提示「数据较少」
  - 1 题：**拒绝出结果**，提示该维度还需要回答 1 题
  - 0 题：**拒绝出结果**，提示该维度缺少有效回答
  - 不足时只能给「回去补答」的入口，**不得替用户选答案**、不得用默认值补齐
- 结果页在有人跳过时追加一句说明：「本次跳过了 X 道题，相关维度根据已回答的题目计算。部分维度的数据较少，结果仅供娱乐参考。」并展示各维实际回答数（如 3/4 题）；没人跳过时整段不出现。

> 为什么不是简单地把跳过当成 0 分：那会把「不想答」变成「这维很差」，直接改变物种判定，等于替用户回答了。
> 为什么保留 4 题分母（`3×n`）而不是按比例缩放到 12：`3×n` 就是「n 题每人最多贡献 3 分」的满量程，等价于「用已回答的题算平均分再映射到 0–100」，n=4 时自然退化成原式。

## 3. 精度纪律（V1.0 硬性）

- 维度指数由原始总分**精确换算**，不做中间四舍五入
- A、R 用未舍入的指数计算
- 所有阈值判断用**整数判据**（十节），不是浮点
- 只在**展示**时格式化为 1 位小数
- 结果页读后端算好的同一份对象，**前端绝不再算一遍**

# 五、判定流程（照着这个顺序写，不能换）

## 第 0 步：输入校验

- 20 个位置必须都「处理过」：要么选了选项，要么主动跳过。既没选也没跳过 → **拒绝出结果**，提示"还有 N 题没处理"，不得用默认值补齐
- 任一维度有效回答 < 2 题（v1.2）→ **拒绝出结果**，按 2.1 的提示语说明缺几题
- 任何一题答案不是 1–4 的整数 → 拒绝，不猜
- 任一维度总分不在 4–16 → 拒绝（全答口径；部分作答由 n 与 S 直接约束）

## 第 1 步：算两个基础量

```
A = (W + L + M + C + G) / 5      五维平均分
R = 五维最高分 - 五维最低分       五维极差
```

## 第 2 步：水豚优先（满足就结束）

```
A >= 50  且  R <= 25   →  水豚
```

含义：整体达标 **并且** 五维不撕裂。**五维都低但很均衡，不算水豚**（全 0 分是树懒，不是水豚——这条有专门的回归用例盯着）。

## 第 3 步：不是水豚，算四个匹配分

```
树懒匹配分   = 0.6 × (100 - L) + 0.4 × (100 - M)
炸毛猫匹配分 = 0.6 × (100 - C) + 0.4 × (100 - M)
狐狸匹配分   = 0.55 × W + 0.45 × G
企鹅匹配分   = 0.55 × L + 0.45 × M
```

取最高者。记忆法：树懒、炸毛猫算的是"缺什么"（越低分越高）；狐狸、企鹅算的是"有什么"（越高分越高）。

## 第 4 步：并列处理（必须固定，不能随机）

固定优先级：**树懒 → 炸毛猫 → 狐狸 → 企鹅**

| 情况 | 怎么判 | 有没有区分力 |
| --- | --- | --- |
| 恰好两个并列，且是「树懒 + 炸毛猫」 | **树懒胜** | **没有**。两式相减 = 0.6×(C − L)，相等 ⇔ L = C。所以"比 L 与 C"永远得到相等，是空操作。371,293 组穷举里这类并列 10,706 组，L≠C 的 **0 组** |
| 恰好两个并列，且是「狐狸 + 企鹅」 | 比 (W+G)/2 与 (L+M)/2，**高者胜**；相等 → 狐狸 | **有**。穷举 719 组：狐狸胜 18、企鹅胜 34、相等 667（相等时按规则取狐狸） |
| 恰好两个并列，其他组合（树懒+狐狸、树懒+企鹅、炸毛猫+狐狸、炸毛猫+企鹅） | 按固定优先级取靠前者 | 没有（规则兜底） |
| 三个或四个同时并列 | 直接按固定优先级，**不做任何维度比较** | 没有（规则兜底） |

> **实现红线**：必须先判断"候选恰好 2 个"，再进特殊规则。写成"候选里同时含树懒与炸毛猫就比 L 与 C"会在三并列时误删第三方候选——旧实现就是这样错的，穷举 371,293 组有 8 组结果与规则不符（例：W/L/M/C/G = 25/100/0/75/91.7 三并列，旧实现给狐狸，正确是炸毛猫）。

**已知副作用（记录，不修改）**：随机作答下 79.5% 的并列都是「树懒+炸毛猫」，而规则固定判给树懒，所以树懒会系统性占优（当前 29.06%，若改为炸毛猫优先则约 26.3%）。这是"信息不足时选固定答案"的必然代价，**不做随机、不做二次猜测**。

## 第 5 步：整体状态（独立于物种）

```
A < 40            → 需要回血
40 <= A < 60      → 勉强维持
60 <= A < 75      → 基本在线
A >= 75           → 状态不错
```

**物种回答"你像哪种状态"，整体状态回答"你过得怎么样"。** 两者分开算，判词可以互相解释，但不能互相覆盖（不能因为分到水豚就把"需要回血"写成"其实还不错"）。

## 第 6 步：副称号

**第一步，选一个维度：**

| 整体状态 | 选哪个 |
| --- | --- |
| 需要回血 | **最低分**维度 |
| 状态不错 | **最高分**维度 |
| 勉强维持 / 基本在线 | 与 A **偏离绝对值最大**的维度，偏离 = ｜维度分 − A｜ |

并列时按 **W → L → M → C → G** 取第一个。"并列"指**该档所用的那个比较量相等**：前两档比维度分，后两档比偏离绝对值。

> 偏离必须取绝对值。若写成有符号（A − 维度分），最低分维度永远胜出，这一档就和"需要回血"完全重合了。

**第二步，按该维度分数查表：**

| 维度 | 低（≤ 33.3） | 中（41.7–66.7） | 高（≥ 75） |
| --- | --- | --- | --- |
| W 钱包 | 月光守门员 | 精打细算选手 | 存款小管家 |
| L 生命值 | 周末失踪人口 | 时间管理选手 | 准点下班选手 |
| M 精神 | 脑内弹幕发射器 | 情绪缓冲选手 | 情绪稳定器 |
| C 气候 | 办公室天气预报员 | 团队观察选手 | 人间职场润滑剂 |
| G 成长 | 原地刷怪选手 | 经验积累选手 | 技能解锁玩家 |

> 文档旧写法用"低于 40 / 40–69 / 70 及以上"，数值上等价（因为指数只有 13 档，40 和 70 本身取不到），V1.0 直接写成实际命中的档位，避免开发按连续值理解。

# 六、整数精确实现（V1.0 参考实现）

浮点写法在边界上不可靠。把维度指数换成整数 **p = 维度原始总分 − 4（0–12）**，全部判据变成整数比较：

| 原判据 | 整数等价判据 | 为什么 |
| --- | --- | --- |
| A ≥ 50 | Σp ≥ 30 | Σp/5 × 100/12 ≥ 50 ⇔ Σp ≥ 30 |
| A < 40 / 60 / 75 | Σp < 24 / 36 / 45 | 同上，逐一换算 |
| R ≤ 25 | p 的最大值 − 最小值 ≤ 3 | 极差 3 档 = 25 分 |
| 树懒匹配分 | 12 × (12 − L) + 8 × (12 − M) | 原式 ×240/100 放大成整数 |
| 炸毛猫匹配分 | 12 × (12 − C) + 8 × (12 − M) | 同上 |
| 狐狸匹配分 | 11 × W + 9 × G | 原式 ×20 放大 |
| 企鹅匹配分 | 11 × L + 9 × M | 同上 |
| 副称号低/中/高 | p ≤ 4 / 5–8 / p ≥ 9 | 33.3 分上界 = p 4；75 分下界 = p 9 |
| 副称号偏离 | ｜5p − Σp｜（整数） | 等价于 ｜维度分 − A｜ 的 5 倍 |

四个匹配分统一在 **240 分制**：树懒/炸毛猫的最大值是 240 分（对应 100 分），狐狸/企鹅同理，可直接比较。

参考实现：`70-质量检查/计算核心.js`（`classifySums` / `classifyAnswers`，全题作答口径）。**开发请照抄这个文件，不要自己重写公式。**

**v1.2 的整数化改法（跳过题目后仍不引入浮点）**：把 `p` 整体放大 12 倍记为 `P`（`P = 12p`）。因为一维有效回答数只可能是 2/3/4，而 `P_d = 48 × (S_d − n_d) / n_d` 恒为整数（48 能被 2/3/4 整除），所以上表所有判据都能平移到 `P` 的整数比较，不需要容差：

| 判据 | 换成 P 之后 |
| --- | --- |
| A ≥ 50 / A < 40·60·75 | ΣP ≥ 360 / ΣP < 288·432·540 |
| R ≤ 25 | P 极差 ≤ 36 |
| 匹配分 | 树懒 = 12×(144−P_L) + 8×(144−P_M)，其余同理（整体 ×12，比大小不变） |
| 副称号低/中/高 | P ≤ 48 / 49–107 / P ≥ 108 |
| 副称号偏离 | ｜5P − ΣP｜ |
| 维度指数 | P × 100 / 144（n=4 时与 p×100/12 是同一个有理数，舍入结果也相同） |

## 第 7 步（v1.2）：缺失答案分支

只有「20 个位置全部处理过、且每维有效回答 ≥ 2」才进到上面第 1–6 步；`n < 4` 时用 2.1 的 `S`、`n` 口径算指数，其余步骤（水豚门槛、匹配分、并列、状态分档、副称号）**一个字都不改**——它们只吃 `p`（现在是 `P`），不关心这个 `p` 是几道题来的。

# 七、五种物种定义

## 数据版本（每次出结果都要记）

| 字段 | 当前值 | 什么时候改 |

# 十三、压测结论（2026-11-02 重算）

**口径**：穷举全部 13⁵ = 371,293 组五维；另用卷积精确计算"20 题每题 1–4 分等概率作答"的分布（4^20 ≈ 1.1 万亿种作答的精确比例，非抽样）。

| 物种 | 五维均匀（理论空间） | 真实作答（精确） | 旧文档 50 万组抽样 |
| --- | --- | --- | --- |
| 树懒 | 29.18% | **29.06%** | 29.8% |
| 企鹅 | 29.98% | **25.55%** | 29.1% |
| 炸毛猫 | 19.90% | **18.94%** | 19.3% |
| 狐狸 | 19.83% | **16.28%** | 19.7% |
| 水豚 | 1.10% | **10.16%** | 9.2% |

> 两种口径差这么多是正常的：答题时维度分会向中间聚，五维均匀是把每个维度当等概率。**给产品决策看"真实作答"那一列**；"五维均匀"只用于检查算法在各区域的表现。
>
> 旧 50 万组用了精度不足的随机数（乘法溢出），数值作废，本次改为精确卷积。

其余结构性结论：

- 并列共 13,463 组（3.63%），其中「树懒+炸毛猫」10,706 组（79.5%）
- 可及的「物种 × 整体状态」组合 16 / 20（不可及：树懒×状态不错、炸毛猫×状态不错、水豚×需要回血、狐狸×需要回血）
- 15 个副称号全部可达；「物种 × 副称号」可及 72 / 75
- 单题 ±1 分：13.15% 会改物种、7.99% 会改整体状态、25.19% 会改副称号、0.76% 三项同时变

详细数据与失败案例：`70-质量检查/算法压力测试报告.md`、`压力测试结果.json`。
