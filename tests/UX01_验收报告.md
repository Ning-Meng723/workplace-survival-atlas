## 三、三项改动逐条对照

### 1. 答题交互

| 要求 | 实现 | 证据 |
| --- | --- | --- |
| 点击选项立即显示选中态 | 先写答案 + 落盘，再更新选中态（`is-selected` + `aria-pressed`），同一帧完成 | U1：点后选中 1 个，index 仍为 0 |
| 延迟约 300–400ms 自动进入下一题 | `AUTO_ADVANCE_MS = 360`，单一 `setTimeout`，新选择会取消旧定时器 | U1：90ms 时 index=0，610ms 后 index=1 |
| 删除主要位置的「下一题」按钮 | 底部操作条只剩「← 上一题」+ 一行状态提示 | U8：`#btn-next` 不存在；截图 S2 |
| 保留「上一题」 | `#btn-prev` 保留，第 1 题禁用 | U3、截图 S1/S2 |
| 触屏左滑下一题 / 右滑上一题 | `touchstart/move/end` 挂在 `#screen-quiz`，位移 ≥ 46px 才触发 | U5：左滑 → index 4，右滑 → index 3 |
| 只有明确横向手势才切题，不影响上下滚动 | 先 >14px 判定方向，`|dx| > |dy|×1.4` 才算横向；只有横向时 `preventDefault` | U5 横向 `prevented=true`；U6 竖向 `prevented=false` 且不切题 |
| 未完成当前题不允许左滑跳过 | `next()` 先查 `answers[q.id]`，缺答案直接拒绝并提示 | U7：第 5 题未答时左滑，index 仍为 4 |
| 选中后答案立即保存 | `selectOption` 内先 `save()`（localStorage）再谈切题 | U2：内存与存档都为 `Q01-O1` |
| 返回上一题仍显示原答案 | 按 `option_id` 复原选中态 | U3：回退后原选中保留=true |
| 桌面浏览器可正常操作 | 点击即自动切题，全程不依赖触屏 | U14：全部导航由 MouseEvent 驱动 |
| 答题页提示文案 | `#quiz-tip` 首行即「选择后自动进入下一题 · 向右滑动可返回上一题」 | U16 逐字比对 |
| 处理连点 / 重复触摸 / 自动切题状态 | ① 单一 `autoTimer`，连点只改选不排队；② 切题后 180ms 忽略选项点击（`tapGuard`）；③ `advance()` 强制校验当前题已有答案；④ 导航节流 120ms | U4：连点两次只前进一题 |

### 2. 删除独立完成页

- `#quiz-complete` 整块 DOM 删除，连同 `#btn-view-result`、`#btn-review`、`#btn-restart-2` 与相关 CSS 一并清掉（无残留死代码）。
- 第 20 题选中 → 保持 360ms 选中反馈（截图可见）→ 校验 20 题齐全 → 算分 → 结果页。
- 不齐就拒绝：`finishToResult()` 先取 `missingIds()`，缺题只提示、不跳转。
- 为不丢「改答案」能力，结果页顶栏补「改答案」（回第 20 题，答案全保留）。这是删掉完成页后必须补的一环，不是新功能。

附加项：U4（连点不跳题）、U12（遮罩 + Esc）、U16（提示文案逐字）、U17（改答案）、U20（零外部请求）。

**U13 的口径说明（重要）**：无头浏览器无法伪造「可信」的滚轮/手指滚动事件，所以这一项验证的是**锁的机制**而不是「模拟一次手指滚动」：

1. 弹窗打开后 `html` 与 `body` 的 `overflow-y` 均为 `hidden`；
2. 视口中心 `elementFromPoint` 命中弹窗内部（背景不可触达）；
3. 遮罩自身不可滚动（设 `scrollTop=400` 仍为 0）；
4. 关闭后 `overflow` 恢复 `visible`，页面能正常滚到指定位置。

早期版本用「弹窗打开时 `window.scrollTo` 是否被拦住」来判断，是**错的口径**：按 CSS 规范 `overflow:hidden` 仍允许程序化滚动，拦住的是用户滚动。该断言已改正并记录在此。

## 六、截图里那条黑色提示条

人工截图出现重复的黑条：「请慢慢滚动页面，或点击自动滚动开始截长图」。

**结论：不是网页元素，是截图工具的覆盖层。**

取证：在 `30-网页产品/web-v1/` 全目录检索 `请慢慢滚动页面` / `点击自动滚动` / `开始截长图`，**零命中**；页面 DOM 里也没有对应节点。按你的要求，**没有为了让截图好看去改网页代码**（例如去加 `display:none` 或改层级）——那会把工具的问题变成产品的技术债。

## 七、失败项与修复过程（如实记录）

| # | 首轮现象 | 根因 | 处理 |
| --- | --- | --- | --- |
| 1 | U4 失败：第 3 题连点两次后 index 停在 2，没前进 | 上一题自动前进后 220ms 的「防连点保护」还在，测试在窗口内就点了，两次点击都被吞 | 保护窗口从 220ms 降到 **180ms**（人体反应时间下限附近）；测试在切换题目后等 300ms 再点。判定逻辑本身没改 |
| 2 | U13 失败：弹窗打开时 `scrollTo` 仍能滚动 | **断言写错了**：`overflow:hidden` 按规范仍允许程序化滚动，拦的是用户滚动 | 改为验证锁机制（overflow 双端 hidden + 中心命中弹窗 + 遮罩不可滚 + 关闭后恢复），并在报告里写明口径 |
| 3 | 截图 S2「选中态」拍到的是下一题 | 选中 360ms 后自动前进，截图工具在虚拟时间末尾才拍，自然拍到下一题 | 截图壳页里点完立刻 `goTo` 同一题取消待执行定时器，只为静帧取景；**产品代码未改** |
| 4 | 结果页 320px 顶栏产品名被挤成两行 | 新增第三个链接后，一行放不下（约 290px > 288px 可用宽） | ≤380px 时顶栏改两排：产品名一行、三个链接右对齐一行 |
| 5 | 分享卡弹窗里卡片边界看不清、关闭按钮出现橙色焦点圈 | 卡片底色与弹窗底色同为纸白；自动聚焦落在按钮上触发 `:focus-visible` | 给卡片加描边 + 轻阴影；焦点改落在弹窗容器（`tabindex="-1"`），键盘仍可 Tab 到按钮 |

其余无失败项。
