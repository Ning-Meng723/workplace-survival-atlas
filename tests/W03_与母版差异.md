# W03 与母版差异说明

## 一、先说结论

**没有改母版。** `70-质量检查/计算核心.js` 一个字节都没动（mtime 仍是 2026-11-02 16:20），
所以任务书要求的「如确实需要修改原计算核心，先制作备份」这一条**不触发**——本次是新建一份移植文件，母版保持原样可随时对照。

**算法语义零改动**：公式、阈值、优先级、并列规则、副称号绝对值判据、整数判据全部照搬。
**证明方式不是嘴说**：`tests/计分验收.js` 用 371,293 组五维组合把两份实现的完整结果对象逐组 `JSON.stringify` 比对，0 组不一致；
再拉真浏览器（Edge/Chromium 156 无头）加载同一份 `scoring.js` 跑同一批 371,293 组，两侧哈希完全相同。

## 二、四处实质改动（逐条对照）

### 改动 1｜版本号：写死常量 → 从题库读

| | 内容 |
| --- | --- |
| 母版（196 行文件第 21–27 行） | `const VERSIONS = { product_id: 'workplace-survival-atlas', question_version: 'v1.0', scoring_version: 'v1.1', algorithm_version: 'v1.0', result_content_version: 'v1.0' }` |
| 网页版 | `var VERSIONS = DEFAULT_VERSIONS;`（同值）+ 新增 `versionsFromBank(bank)` 从 `bank.meta.数据版本` 读 5 个键 + `resolveVersions()` 统一兜底 |
| 为什么 | 上线清单 1.13 要求「版本号从题库读出，不是写死」。写死后一旦升 `scoring_version`，网页会继续报旧号 |
| 算法影响 | **无**。版本号只是随结果带出的留档字段，不参与任何判断 |
| 兼容性 | `classifySums / classifyIndices` 不传版本时行为与母版完全一致（`DEFAULT_VERSIONS` 与母版同值） |

### 改动 2｜导出方式：`module.exports` → UMD

| | 内容 |
| --- | --- |
| 母版 | `module.exports = { ... }`（只认 Node） |
| 网页版 | IIFE 包裹：有 `module.exports` 就挂 CommonJS；否则挂 `window.WorkplaceScoring` |
| 为什么 | 让 **Node 验收脚本与网页共用同一份文件**，避免「网页一份、验收一份」两套实现 |
| 算法影响 | **无** |
| 兼容性 | `require('./js/scoring.js')` 拿到的对象与母版导出的键**只多不少**（多 5 个适配层导出），E11 已断言 |

### 改动 3｜错误对象：`class extends Error` → 原型构造

| | 内容 |
| --- | --- |
| 母版 | `class ScoreError extends Error { constructor(code, message) { super(message); this.code = code; } }` |
| 网页版 | `function ScoreError(...)` + `ScoreError.prototype = Object.create(Error.prototype)` + `this.name = 'ScoreError'` |
| 为什么 | 部分旧版安卓 WebView / 旧版微信内核不支持 `class` 继承 `Error`（会丢 stack 或 instanceof 失效） |
| 算法影响 | **无**。错误码、提示文案、`instanceof Error`、`stack` 全部保留，E11 逐项断言 |
| 差异风险 | 若将来有代码用 `ScoreError.name` 直接判断类名，请改用 `code` 字段（本来也该用 code） |

### 改动 4｜`classifyAnswers / classifyIndices / finish` 增加可选参数 `versions`

| | 内容 |
| --- | --- |
| 母版 | `classifyAnswers(answers, questionSumsMap)` / `classifyIndices(indices)` |
| 网页版 | 增加第三个 / 第二个可选参数：可传 5 个版本号对象，也可直接传整份 `bank` |
| 为什么 | 让调用方能指定版本号来源，而不必依赖写死常量 |
| 算法影响 | **无**。不传参 = 母版行为；传参只影响结果对象里的 `versions` 字段 |
| 兼容性 | 老调用（2 个参数 / 1 个参数）签名不变，E2/E9 全部用老签名跑通 |

## 三、新增的适配层（不属于算法改造，母版里没有这一步）

母版只接受 `scores[20]` 分值数组；网页收到的是 `option_id`。这一步在母版里不存在，所以是新增而非修改。

| 函数 | 作用 | 红线 |
| --- | --- | --- |
| `buildScoreInput(bank, answers)` | 校验题库 20 题 → 每题用 `option_id` 在**该题自己的 4 个选项**里查 → 产出 `scores[20]` + `dimMap[20]` | 只 `option_id` 精确匹配；**不读数组下标、不读字母、不读选项文字** |
| `scoreBank(bank, answers)` | 一站式：`buildScoreInput` + `classifyAnswers` + 从题库读版本号 | 缺题 → `INCOMPLETE` 并带 `remaining` / `missing`；非法 `option_id` → `BAD_ANSWER` |
| `versionsFromBank(bank)` | 从 `meta.数据版本` 取 5 个版本号，缺字段直接抛 `BAD_INPUT` | 不做默认值兜底（缺就报错，避免悄悄用旧号） |

## 四、语法降级清单（不影响逻辑，但必须告知）

为兼容旧版 WebView，整份文件从 ES6 降到 ES5。逐个函数**逻辑未变**，只是写法降级：

| 项目 | 母版 | 网页版 | 影响 |
| --- | --- | --- | --- |
| 变量声明 | `const` / `let`（43 处） | `var` | 无（无块级作用域依赖） |
| 函数 | 箭头函数（11 处） | `function` | 无（箭头函数内没有 `this` 引用） |
| 类 | `class ScoreError extends Error` | 原型构造 | 见改动 3 |
| 数组展开 | `{ ...VERSIONS }` / `{ ...dimSums }` | 显式逐字段赋值 | 无（字段集合相同、顺序相同） |
| 查找 | `Array.prototype.find` | `filter(...)[0]` | 无（结果等价，`find` 在 ES6 才标准化） |
| 取大/取小 | `Math.max(...arr)` | `Math.max.apply(null, arr)` | 无 |
