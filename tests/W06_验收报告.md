## 三、N12：槽位定义源文件修正

### 3.1 改前（病根）

`结果文案规范.md` 四节槽位表把两个槽位写成**合并行**，`生成结果文案.js` 会把同一份「内容/示例」复制给两个 key：

```md
| `{最高维}` / `{最高分}` | 最高分维度 | 钱包回血 83.3 |
```

结果 `{最高维}` 的示例变成了带分数的「钱包回血 83.3」，照填会生成「83.3 有 83.3 分」这类病句。

### 3.2 改后

```md
| `{最低维}` | 五维中分数最低的**维度名称**（取自二节「文案名」，不是分数） | 精神状态稳定指数（即文案名「精神状态稳定」） |
| `{最低分}` | 该维度指数（保留 1 位） | 33.3 |
| `{最高维}` | 五维中分数最高的**维度名称**（取自二节「文案名」，不是分数） | 钱包回血指数（即文案名「钱包回血」） |
| `{最高分}` | 该维度指数（保留 1 位） | 83.3 |
```

并在表下补一条**填槽纪律**说明：维度槽只能填维度名称、分数只由 `{最高分}/{最低分}` 提供、名称一律取自二节「文案名」列不自创。

- 拆行后 `结果文案.json` 的 `槽位定义` 为 **6 个独立 key**：`最低维 / 最低分 / 最高维 / 最高分 / A / R`。
- 示例采用你给的口径「钱包回血指数」，同时括号注明实际填充值来自二节文案名，避免与「文案里统一用这套，别自创」冲突。
- **未新增正式判词、未改其他结果文案**；N14 三处多余空格按你的决定**暂缓未动**。
- 同步更新 `tests/三者联调.js` 里 2 处已过时的 N12 注释（只是注释，不影响测试逻辑）。
