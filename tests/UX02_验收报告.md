## 二、先做的核对：现有实现与版本语义

### 2.1 `scoring.js` 原来的样子（为什么不能直接加跳过）

| 位置 | 现状 | 对跳过的阻碍 |
| --- | --- | --- |
| `classifySums(dimSums)` | 只接受 **4–16 的整数**维度总分，内部 `p = sum − 4 ∈ 0..12` | 少答 1 题，总分只有 3–12，直接被 `BAD_INPUT` 拦下 |
| `classifyAnswers(answers, dimMap)` | **强制 `answers.length === 20`**，否则 `INCOMPLETE` | 天然不支持缺题 |
| 全部阈值 | 用整数判据（`Σp ≥ 30`、`p 极差 ≤ 3`…），**不允许浮点比较** | 少答后 `p` 变成 4/3、2 这类分数，整数判据立刻失效 |
| 维度指数 | 只可能有 13 个值（8.33 的整数倍） | 少答后会出现 44.4 这类非格点值，`NOT_GRID` 会误报 |
| `计分验收.js` E2 | 用 `JSON.stringify` **逐字节比对网页版与母版** | 只要给结果对象加一个字段，E2 立刻全挂 |

**所以这次不是「加个 if」，而是要把「整数判据」这套地基从「一维 4 题」推广到「一维 n 题」而不引入浮点。**

### 2.2 版本语义（`20-测试内容/题库版本记录.md` 二节原文）

| 改动类型 | 动哪个号 |
| --- | --- |
| 改题干 / 选项文案（分值不变） | `question_version` +0.1 |
| 改任何选项的分值 / 改 option_id | `scoring_version` +0.1 |
| **改判定公式、阈值、并列规则** | **`algorithm_version` +0.1** |
| 改结果文案、判词、副称号、台词 | `result_content_version` +0.1 |

### 2.3 判断过程（为什么升两个号）

1. **公式变了 → `algorithm_version` +0.1，没有争议。**
   `维度指数 = (S−4)/12×100` 变成 `((S−n)/(3n))×100`，定义域从「S ∈ 4..16」扩到「S ∈ n..4n」，并新增「每维 ≥ 2 题」阈值。这两项都落在「判定公式、阈值」这一行。
2. **`scoring_version` 要不要动，取决于「题库 `scoring` 段算不算 scoring」——而它算。**
   `70-质量检查/版本快照.js` 给 `题库.json` 的 **`scoring` 段**算了独立的 sha256（`指纹.scoring`），并在 `版本快照` 检查里写死一条：**`scoring` 指纹变了就必须升 `scoring_version`**。
   这次按「改算法必须同步改规则书」（`题库版本记录.md` 三节「常见错误做法」第 5 条）把 `scoring` 段补上了跳过规则文本，指纹由 `c07268bb82b01cae` → **`4ee6c13663269f3f`**。
   → 不升 `scoring_version` 的话，`版本快照.js` 会直接报错，只能靠「放宽校验」蒙过去，这不可接受。
3. **`question_version` 不动**：20 题题干、选项文案、option_id 全部一字未改（`questions` 指纹仍 `3de2acfc7eb04af8`）。
4. **`result_content_version` 不动**：判词、副称号、台词、卡片规范都没改。**结果页那句「本次跳过了 X 道题…」是功能性提示，写在 `index.html` 里，不进 `结果文案.json`**——如果把它塞进文案库，就必须重跑 `生成结果文案.js` 并升 `result_content_version`，而本轮明确要求不动这个号。这一点请你确认是否接受（见第九节）。

> 结论：**`algorithm_version` v1.1 + `scoring_version` v1.2 同时升**，是这套版本管理约定下的唯一自洽解；两个号对应两件真实发生的事（公式/阈值变了 / 题库计分规则段变了）。

## 四、公式与整数化（这次真正的技术难点）

任务书给的公式：`index_d = ((S_d − n_d) / (3 × n_d)) × 100`。

- `n_d = 4` → `(S−4)/12×100`，与 v1.1 **同一个式子**；
- `n_d = 3` → 步长 11.1，会出现 44.4 这种非 13 档值；
- `n_d = 2` → 步长 16.7（恰好都落在格点上）。

**不能直接上浮点**（D020 的老账：浮点版在 2,236 组上算错 0.60%）。做法是把 `p` 放大 12 倍：

```
P_d = 12 × p_d = 48 × (S_d − n_d) / n_d       （n ∈ {2,3,4} 都能整除 48 → 恒为整数）
```

| 原判据（`p`） | 换到 `P`（整数比较） | n=4 时是否等价 |
| --- | --- | --- |
| `A ≥ 50` | `ΣP ≥ 360` | ✅ `ΣP = 12Σp` |
| `A < 40 / 60 / 75` | `ΣP < 288 / 432 / 540` | ✅ |
| `R ≤ 25` | `P 极差 ≤ 36` | ✅ |
| 树懒匹配分 `12(12−p_L)+8(12−p_M)` | `12(144−P_L)+8(144−P_M)`（整体 ×12） | ✅ 比大小不变 |
| 狐狸匹配分 `11p_W+9p_G` | `11P_W+9P_G`（整体 ×12） | ✅ |
| 副称号档位 `p≤4 / 5–8 / p≥9` | `P≤48 / 49–107 / P≥108` | ✅ |
| 副称号偏离 `|5p−Σp|` | `|5P−ΣP|` | ✅ |
| 维度指数 `p×100/12` | `P×100/144` | ✅ 同一有理数、同一舍入 |

`A`、`R` 也按放大后的整数算：`A = ΣP×5/36`、`R = ΔP×100/144`——分子分母同乘 12，商完全一样，所以 **371,293 组全答结果的浮点值逐字节相同**（`计分验收.js` E2 已验证 0 差异）。

> 附带收获：`n=2` 时 `P` 一定是 24 的倍数，指数必然落在 13 档格点上；`n=3` 才会出现非格点值（保存为 N18，属公式必然结果，不是缺陷）。
